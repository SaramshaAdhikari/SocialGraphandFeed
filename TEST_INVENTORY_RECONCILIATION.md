## 3. Forensic Reconciliation of Historical Questions

### 3.1 The "292 vs. 298" Test Count Discrepancy
- **Question**: Why did early reports cite 292 unit tests while subsequent monorepo summaries referenced 298 tests?
- **Audited Resolution**:
  - `packages/frontend/src/test`: Contains exactly **292** Vitest tests across 23 component test files.
  - `packages/backend/test/serialization.test.ts`: Contains exactly **6** unit tests exercising date and BSON serialization without database dependencies.
  - Total Monorepo Fast Unit Tests: $292 + 6 = \mathbf{298}$.
  - Both numbers are correct within their respective workspace boundaries. The monorepo total is **298**, and the frontend-only total is **292**.

---

### 3.2 The "382 True Assertions vs. 7,121+ Assertions" Discrepancy
- **Question**: Why did early testing drafts claim "7,121+ assertions passed" across the 32 testing techniques?
- **Audited Resolution**:
  - The figure "7,121+" was generated by counting repeated iterations inside synthetic matrix loops (e.g. fuzzing generators, 100-cycle concurrency simulation loops, multi-byte character permutations).
  - The **actual, explicit automated assertions** (`expect()`, `assert()`, `Value.Check()`) across the 32 standalone testing technique scripts total **382**.
  - All 32 reports under `TESTS/` have been updated to report the true count of **382 automated assertions**.
